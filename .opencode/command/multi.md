# Мульти-агентный запуск

Задача пользователя: **$ARGUMENTS**

Ты — архитектор. Выполни задачу силами команды, максимально используя параллелизм.

## Обязательный порядок действий

### 1. Анализ и план
- Изучи текущее состояние репозитория (структура, стек, существующие соглашения) через `read`, `glob`, `grep`.
- Сформулируй архитектурное решение: какие модули/файлы затрагиваются, какие контракты между бэком и фронтом, какие сценарии нужно протестировать.
- Разбей работу на три независимых трека:
  - **Backend**: что делает `coder-backend`
  - **Frontend**: что делает `coder-frontend`
  - **Tests**: что делает `coder-tests`
- Зафиксируй контракты (типы данных, сигнатуры API, имена компонентов/хуков) — они общие для всех треков.

### 2. Параллельный запуск подагентов
Отправь **одним сообщением** три вызова `task` одновременно:

1. `task` → `coder-backend` с детальным ТЗ на серверную часть
2. `task` → `coder-frontend` с детальным ТЗ на клиентскую часть
3. `task` → `coder-tests` с детальным ТЗ на тесты

В каждом промпте обязательно укажи:
- Контекст общей задачи
- Согласованные контракты (одинаковые во всех трёх промптах в соответствующих частях)
- Точные пути файлов для создания/изменения
- Критерии готовности
- Что вернуть в финальном ответе

### 3. Интеграция и ревью
- Получив результаты от всех трёх подагентов, проверь согласованность: совпадают ли контракты, нет ли пересечений, всё ли покрыто.
- Если есть расхождения — исправь точечно сам через `edit` или отправь уточняющий `task` нужному кодеру.
- Запусти тесты (если применимо), убедись что они зелёные.

### 4. Итоговый отчёт пользователю
Сформируй краткую сводку:
- Архитектурные решения (1–3 пункта)
- Что сделано каждым треком (список файлов + суть)
- Результат запуска тестов
- Что пользователю нужно сделать для запуска (миграции, зависимости, env)
- Открытые вопросы или следующие шаги

## Правила

- **Не делай последовательно то, что можно параллельно.** Три кодера должны стартовать одновременно.
- **Не кодь сам крупные блоки.** Твоя работа — декомпозиция, контракты, интеграция, ревью.
- **Контракты фиксируются ДО запуска подагентов.** Изменение контракта по ходу = переделка в нескольких треках.
