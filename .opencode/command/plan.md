# Планирование

Задача: **$ARGUMENTS**

Режим: **только планирование**. Никакого кода не пишем, файлы не меняем.

## Порядок действий

1. **Изучи контекст.**
   - Прочитай `AGENTS.md` и ключевые конфиги (`opencode.json`, `pyproject.toml`, `package.json`) если ещё не читал.
   - По необходимости делегируй `researcher` через `task`, чтобы собрать контекст по релевантным частям кодовой базы.
   - Не начинай план, пока не понимаешь текущее состояние.

2. **Разработай план.**
   Сформулируй:
   - **Цель:** что должно получиться в итоге (одно-два предложения)
   - **Архитектурные решения:** какие модули/слои затрагиваются, какие контракты между ними, какие технические выборы нужно сделать (и их обоснование)
   - **Декомпозиция:** задачи по трекам
     - Backend (`coder-backend`): список подзадач + файлы
     - Frontend (`coder-frontend`): список подзадач + файлы
     - Tests (`coder-tests`): сценарии покрытия
     - DevOps (`devops`), если нужно: миграции, env, compose
   - **Контракты:** типы/сигнатуры API/схемы, общие для треков
   - **Порядок выполнения:** что можно параллельно, что последовательно, почему
   - **Риски и открытые вопросы:** что неясно, что может пойти не так
   - **Критерии готовности:** как поймём, что задача сделана

3. **Выведи план пользователю** в читаемом структурированном виде.

4. **Жди подтверждения.** Не запускай кодеров, не меняй файлы. После одобрения плана пользователь сам решит, запускать ли `/multi` или делать иначе.

## Правила

- **Никаких `write` / `edit` в этой команде.** Только `read`, `grep`, `glob`, `bash` (для `git status` и подобного), `task` (только для `researcher`).
- **Конкретика важнее красоты.** План должен быть таким, чтобы по нему можно было сразу запускать работу, без домысливания.
- **Честность о неопределённости.** Если чего-то не знаешь — пиши в «открытые вопросы», а не выдумывай.
