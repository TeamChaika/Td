# Code Review

Цель: провести независимое ревью текущих изменений в репозитории.

Область ревью: **$ARGUMENTS** (если пусто — ревью всех незакоммиченных изменений, `git diff` + `git status`).

## Порядок действий

1. **Собери диапазон изменений.**
   - Если пользователь указал файлы/папки — ревью только их.
   - Иначе: запусти `git status` и `git diff` (если это git-репо), составь список изменённых файлов.
   - Если это отдельная фича — определи, какие файлы к ней относятся.

2. **Запусти подагента `reviewer`** через `task`:
   - Передай список файлов для ревью
   - Дай контекст: что это за задача, какие были архитектурные решения (если знаешь)
   - Попроси вернуть отчёт в стандартном формате (блокеры / замечания / наблюдения / статические проверки / вердикт)

3. **Получив отчёт, прими решение:**
   - Если вердикт ✅ — сообщи пользователю, что всё чисто
   - Если ⚠️ замечания — суммаризируй, предложи исправить через кодеров (сам не правь крупное)
   - Если ❌ блокеры — перечисли их, создай план исправления
     - Для каждого блокера определи: какому кодеру (`coder-backend` / `coder-frontend` / `coder-tests`) это исправлять
     - По запросу пользователя — запусти кодеров параллельно для исправлений
     - После исправлений — запусти `reviewer` повторно

4. **Итоговый ответ пользователю:**
   - Вердикт ревью
   - Ключевые замечания (коротко)
   - Что сделано по исправлениям (если делались)
   - Что осталось (если осталось)

## Правила

- Не правь код сам в рамках этой команды без явного согласия пользователя — только координируй.
- Если `reviewer` нашёл блокер, но пользователь не просит исправлять — просто отчитайся и жди решения.
- Если изменений нет — честно скажи, что ревьюить нечего.
