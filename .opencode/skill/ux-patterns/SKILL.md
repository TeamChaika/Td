# UX Patterns

## Состояния интерфейса — всегда четыре

Для любого view, подтягивающего данные, покрой:

1. **Loading** — что-то происходит
2. **Empty** — данных нет (первый раз, после фильтра)
3. **Error** — что-то сломалось
4. **Success** — данные есть

Никогда не показывай пустой экран «между состояниями». Если данных нет — покажи empty state с CTA.

### Loading — что использовать

- **Skeleton** — когда известна структура финального контента (карточки, таблицы). Лучше спиннера: показывает, что будет, снижает воспринимаемое время.
- **Spinner** — для действий без структуры (отправка формы, короткое ожидание).
- **Progress bar** — для задач с измеримым прогрессом (загрузка файла, multi-step).
- **Optimistic UI** — для быстрых действий (лайк, добавление в корзину): сразу показываем результат, откатываем при ошибке.

Не показывай спиннер раньше 200ms — мигание хуже, чем задержка. `setTimeout` → спиннер только если реально долго.

### Empty state

Обязательные элементы:
- **Иллюстрация или иконка** (не кричащая)
- **Заголовок:** что здесь должно быть, но нет. «У вас пока нет платежей»
- **Пояснение:** почему и что делать. «Платежи появятся здесь, когда клиенты начнут платить.»
- **CTA:** главное действие. «Создать платёжную ссылку»

Разный empty state для разных причин: «нет данных впервые» ≠ «нет данных после фильтра».

### Error state

- **Не показывай стек-трейс.** Пользователю он не нужен.
- **Скажи что произошло** простыми словами: «Не удалось загрузить список. Проверьте соединение.»
- **Дай действие:** кнопка «Повторить», «Назад», «Связаться с поддержкой».
- **Код ошибки** — мелко внизу, чтобы пользователь мог переслать в саппорт. Не главное.
- **Различай типы:** 404 ≠ 500 ≠ offline ≠ 403. Каждому — своё сообщение.

## Формы

### Валидация

- **On blur, не on change** для ошибок. Не ори на человека, пока он печатает.
- **После первой попытки submit** — переключайся на on-change, чтобы пользователь сразу видел, как исправляет.
- **Подтверждение корректности** — зелёная галочка для полей, которые пользователь заполнил (email, пароль). Не только ошибки.
- **Ошибки сервера** — рядом с полем, не в общем toast.
- **Общие ошибки** (сеть, 500) — сверху формы, не у полей.

### Поля

- **Label всегда видим.** Плейсхолдер ≠ label. Пропадает при вводе, путает.
- **Автокомплит:** `autocomplete="email"`, `"current-password"`, `"name"`. Без этого браузер не помогает.
- **Inputmode:** `inputmode="numeric"` для чисел, `"email"` для email — клавиатура на мобильном меняется.
- **Required ≠ «звёздочка после label».** Можно наоборот помечать необязательные «(опционально)», если обязательных больше.
- **Подсказки** — под полем, не в tooltip. Tooltip-only на мобильном недоступен.

### Submit

- **Disable кнопку** во время отправки + спиннер на ней.
- **Не disable кнопку** пока форма невалидна — лучше дай нажать и покажи ошибки. Disabled кнопка не объясняет почему.
- **После успеха** — либо редирект, либо очистка формы + toast «Сохранено».
- **Предотвращение двойной отправки** — обязательно (идемпотентность на бэке + disable на фронте).

### Паттерны длинных форм

- **Группируй** по смыслу, с заголовками секций.
- **Сохраняй прогресс** (localStorage), если форма > 5 полей.
- **Stepper/Wizard** для очень длинных: 3–7 шагов, видимый прогресс, возможность вернуться.
- **Inline vs modal vs page** — зависит от контекста. Модалка для быстрого создания, страница для сложных.

## Подтверждения разрушительных действий

- **Destructive confirm** обязателен для: удаление, отмена платежа, логаут из всех сессий.
- **Кнопка подтверждения красная**, справа. Отмена — слева, нейтральная.
- **Явный текст:** «Удалить платёж #12345?» Не «Вы уверены?» без контекста.
- **Type-to-confirm** для необратимых действий (удаление проекта): пользователь вводит имя объекта.
- **Undo > confirm** где возможно. «Удалено. [Отменить]» в toast на 10 сек — удобнее, чем модалка каждый раз.

## Toast / Snackbar

- **Позиция:** bottom-center или bottom-right на десктопе, top на мобильном (внизу палец закрывает).
- **Длительность:**
  - Success: 3–5 сек
  - Error: не исчезает сам, только по клику
  - Info: 5 сек
- **Одно действие** максимум (Undo, Retry). Не пихай меню.
- **Ограничение:** не более 3 одновременно, остальные в очередь.
- **Важные события** (ошибка платежа) — не toast, а модалка или inline-ошибка.

## Навигация

### Принципы

- **3 клика — миф.** Не важно сколько кликов, важно чтобы каждый был уверенным.
- **Breadcrumbs** для глубоких иерархий (> 2 уровней).
- **Активное состояние** видно всегда: где я сейчас?
- **Мобильная навигация:** bottom tab bar (iOS/Android паттерн) или бургер. Не смешивай.

### Search & Filter

- **Поиск** — мгновенный (debounce 150–300ms), с highlight совпадений.
- **Пустой результат поиска** — отдельный empty state: «Ничего не найдено по запросу "xxx". Попробуйте…»
- **Фильтры:** показывай активные (chips), позволяй сбросить по одному и все.
- **URL state:** фильтры/поиск/сортировка в query params. Пользователь должен мочь поделиться ссылкой с тем же view.

## Feedback действий

- **Мгновенный визуальный отклик** на любое действие (клик → подсветка, hover → изменение).
- **Haptic feedback** на мобильном для важных действий (iOS/Android API).
- **Sound** — по умолчанию off, включается опционально.
- **Долгие действия** (> 1 сек) — прогресс + возможность отмены.

## Микроанимации

### Когда использовать

- **Ориентация:** переход между view — откуда-куда (slide), чтобы не терять контекст.
- **Feedback:** изменение состояния кнопки, лайка, свайпа.
- **Attention:** подсветить важное (shake при ошибке, pulse на нотификации).

### Правила

- **Короткие:** 150–300ms. Дольше — раздражает.
- **Easing:** `ease-out` для входа, `ease-in` для выхода. Никогда `linear` для движения.
- **`prefers-reduced-motion`** уважай. Отключай анимации для тех, кто их не хочет:
  ```css
  @media (prefers-reduced-motion: reduce) {
    * { animation: none !important; transition: none !important; }
  }
  ```
- **Не анимируй всё одновременно.** Иерархия: сначала главное, потом второстепенное, с задержкой.
- **Производительность:** `transform` и `opacity` — дёшево. `width`, `height`, `top`, `left` — дорого (layout reflow).

## Онбординг

- **Progressive disclosure.** Не вали на пользователя всё сразу. Показывай функции в момент их полезности.
- **Tooltips в первом запуске** — только для неочевидного. Если UI нужен 5 тултипов, UI плохой.
- **Пропустить** всегда доступно. Не делай онбординг обязательным.
- **Empty states как онбординг** — показывают, что здесь будет и как это получить.

## Accessibility в UX

- **Focus visible.** `outline` не убирай без замены — пользователи клавиатуры должны видеть, где фокус.
- **Keyboard navigation** для всего. Tab по порядку, Esc закрывает модалки, Enter активирует.
- **Цвет ≠ единственный сигнал.** Красный + иконка ошибки, зелёный + галочка. Дальтоники.
- **Контраст:** текст 4.5:1, крупный текст 3:1 (WCAG AA).
- **Целевые области** минимум 44×44px на touch.

## Антипаттерны

- ❌ Спиннер вместо skeleton при загрузке списка
- ❌ «Success» без объяснения что именно получилось
- ❌ Disabled submit-кнопка без объяснения причины
- ❌ Модалка поверх модалки
- ❌ Auto-focus на поле, которое вне viewport на мобильном (скроллит страницу)
- ❌ Tooltip с важной информацией (недоступно на touch)
- ❌ Infinite scroll для контента, где нужен footer (футер недостижим)
- ❌ Toast для критической ошибки (исчезает, пропускают)
- ❌ Анимация > 500ms для повседневных действий
- ❌ «Are you sure?» без контекста
