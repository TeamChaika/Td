# PayTools — Правила для агентов

Этот документ задаёт общие правила и соглашения, которые обязаны соблюдать все агенты при работе с этим репозиторием.

## Обзор проекта

**PayTools** — набор инструментов для работы с платёжными системами.

### Технологический стек

**Backend (Python):**
- Python 3.11+
- FastAPI для HTTP API
- Pydantic v2 для схем и валидации
- SQLAlchemy 2.x (async) + Alembic для БД
- PostgreSQL как основная БД
- pytest + pytest-asyncio для тестов
- uv или poetry для зависимостей
- ruff + mypy для линта и типов

**Frontend (TypeScript):**
- TypeScript (strict mode)
- React 18+ / Next.js App Router (по ситуации)
- TanStack Query для серверного состояния
- Zod для валидации
- Tailwind CSS
- Vitest + Testing Library для unit/integration тестов
- Playwright для e2e
- pnpm для зависимостей
- ESLint + Prettier

## Общие правила для всех агентов

1. **Читай перед тем, как писать.** Перед изменением файла всегда прочитай его. Перед добавлением новой сущности — убедись, что аналогичной нет.
2. **Следуй существующим паттернам.** Стиль, неймниг, структура импортов — как в соседних файлах. Не переизобретай.
3. **Не коммить секреты.** Никаких API-ключей, токенов, паролей в коде. Всё через `.env` и `pydantic-settings` / переменные окружения.
4. **Не удаляй чужое без необходимости.** Если файл/функция кажутся лишними — спроси у архитектора, не удаляй молча.
5. **Никаких TODO без тикета.** Если чего-то не хватает — сообщи архитектору в финальном ответе, а не оставляй `# TODO: fixme`.
6. **Минимальные зависимости.** Новый пакет добавляй только если действительно нужен. Сначала проверь, нет ли уже аналога.
7. **Комментарии на русском, код на английском.** Переменные, функции, классы, API-поля — английский. Docstrings и комментарии, объясняющие «почему», — русский.

## Соглашения — Backend (Python)

### Стиль кода
- **Форматирование:** `ruff format` (дефолт, 88 символов).
- **Линт:** `ruff check` с набором `E, F, I, B, UP, N, RUF`.
- **Типы:** полная типизация, `mypy --strict` проходит. Без `Any`, кроме границ с внешним миром.
- **Импорты:** абсолютные от корня пакета (`from paytools.domain...`).

### Архитектура
- Слои: `api` → `domain` → `db`. Зависимости только сверху вниз.
- FastAPI-роутеры — тонкие: парсинг запроса, вызов сервиса, формирование ответа. Логику — в `domain`.
- Доменные сервисы принимают зависимости через конструктор (DI через FastAPI `Depends`).
- SQLAlchemy-модели не утекают из `db` наружу — наружу только Pydantic-схемы.

### API
- Все эндпоинты — под `/api/v1/...`.
- Запросы и ответы — Pydantic-схемы в `api/schemas/`.
- Ошибки — через `HTTPException` с кодами и сообщениями в едином формате `{ "error": { "code": "...", "message": "..." } }`.
- Все эндпоинты документируются: `summary`, `description`, `responses`.

### БД
- Все изменения схемы — через Alembic-миграции. Вручную ALTER не делаем.
- Имена таблиц — `snake_case`, во множественном числе (`payments`, `users`).
- Все таймстемпы — `TIMESTAMPTZ` в UTC.

### Тесты
- `pytest` + `pytest-asyncio`. Fixtures — в `conftest.py`.
- БД в тестах — изолированная (transactional rollback или testcontainers).
- Покрытие критичной логики доменного слоя — обязательно.

## Соглашения — Frontend (TypeScript)

### Стиль кода
- **Форматирование:** Prettier (дефолт + `singleQuote: true`).
- **Линт:** ESLint с `@typescript-eslint/recommended` и `react-hooks`.
- **TypeScript:** `strict: true`. Без `any`, кроме границ с внешним миром.
- **Импорты:** path aliases (`@/components`, `@/lib`), не `../../../`.

### Архитектура
- Компоненты: `PascalCase.tsx`, хуки: `useThing.ts`, утилиты: `camelCase.ts`.
- `features/` — самодостаточные фичи (UI + локальная логика + API-интеграция).
- `components/ui/` — переиспользуемые презентационные компоненты.
- Запросы к API — только через `lib/api` (единый клиент с типами).

### Состояние
- Серверные данные — TanStack Query, не в глобальном сторе.
- Клиентское состояние — локальный `useState` или Zustand для реально глобального.
- Формы — React Hook Form + Zod.

### Стили
- Tailwind utility-first. Кастомные классы — только для сложных паттернов.
- Дизайн-токены — через Tailwind theme, не хардкод.

### Тесты
- Vitest + Testing Library для компонентов и хуков.
- Playwright для критичных пользовательских сценариев.
- Моки API — через MSW.

## Git / Коммиты

- Conventional Commits: `feat:`, `fix:`, `refactor:`, `test:`, `chore:`, `docs:`.
- Сообщения — на английском, императив, до 72 символов в заголовке.
- Один коммит = одно логическое изменение.
- **Агенты не делают git-коммиты без явного запроса пользователя.**

## Скилы (`.opencode/skill/`)

Скилы — самозагружаемые markdown-инструкции с проверенными паттернами. Агенты подгружают их через инструмент `skill` под задачу.

- **`responsive-design`** — mobile-first вёрстка, брейкпоинты Tailwind, container queries, fluid typography, touch targets, тёмная тема, адаптивные паттерны (грид карточек, навигация, формы).
- **`web-performance`** — Core Web Vitals (LCP/INP/CLS), bundle size, изображения (AVIF/WebP, `next/image`), шрифты (`next/font`, subset, display: swap), кеширование, RSC/ISR, third-party scripts.
- **`ux-patterns`** — состояния интерфейса (loading/empty/error/success), формы и валидация, подтверждения разрушительных действий, toast/snackbar, навигация, search/filter, feedback, микроанимации, онбординг, accessibility в UX.

Правило для фронтенд-кодера: при любой UI-задаче сначала подумай, какой скил релевантен, и подгрузи его. Это быстрее и надёжнее, чем реализовывать «из головы».

## MCP-серверы (глобально)

Настроены в `~/.config/opencode/opencode.json`, доступны всем проектам:

- **`context7`** (Upstash) — актуальная документация библиотек. Используй через `resolve-library-id` → `get-library-docs` когда нужна точная сигнатура API. Не выдумывай вызовы — запрашивай доку.
- **`supabase`** — управление конкретным Supabase-проектом (ref в `SUPABASE_PROJECT_REF`). **Полный доступ**: схема БД, миграции, RLS, edge functions, SQL. Деструктивные операции — только с подтверждения пользователя.
- **`docker`** — управление локальным Docker daemon. Контейнеры, образы, сети, тома, логи.

### Секреты для MCP

В `.env` (не коммитится):
- `SUPABASE_ACCESS_TOKEN` — personal access token из дашборда Supabase
- `SUPABASE_PROJECT_REF` — ref проекта (из URL дашборда)

См. `.env.example` для шаблона.
