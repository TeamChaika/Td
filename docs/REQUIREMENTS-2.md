## Раздел A. Депозиты (ГЛАВНОЕ)

> Ты упомянул: «Система депозитов если это кафе или ресторан подвязанная к билету».
> Это ключевая фича, которая даёт название продукту (**T**ickets & **D**eposits Pay). Нужно точно понять сценарий.

### A.1. Что такое «депозит» в твоём сценарии?

- [ ] **(A) Минимальный чек / предоплата заказа.**
  Гость покупает билет за 2000 ₽, из них, допустим, 1500 ₽ — это «депозит на заказ». На входе кассир заведения видит: «у этого гостя предоплачено 1500 ₽». Гость заказывает еду/напитки, в конце:
  - съел на 2500 → доплачивает 1000
  - съел на 1000 → остаток 500 сгорает (или возвращается — см. ниже)

- [ ] **(B) Предоплаченный баланс в заведении.**
  Гость кладёт N ₽ на «карту посетителя» (аналог клубной карты). Тратит в кафе со скидкой/без. Баланс живёт между событиями.

- [ ] **(C) Платная бронь столика.**
  Депозит = гарантия бронирования. Например, 3000 ₽ за стол на 4 персоны. Пришёл → сумма идёт в счёт заказа. Не пришёл → сгорает.

- [ ] **(D) Возвратный залог.**
  За инвентарь, VIP-комплект, костюм и т.п. Возвращается после события при сдаче целым.

- [ ] **(E) Комбинация A+C** (билет + предоплата заказа + бронь стола одновременно)

- [ ] **(F) Несколько типов на выбор организатора** — каждый организатор сам решает, какую модель депозита использовать для своего события. (Самый гибкий, но самый сложный вариант.)

- [x] **(G) Свой вариант** → Билеты покупаются отедельно, после чего хостес связывается с гостями и уточняет нужен ли им стол. Если да озвучивает сколько будет стоит депозит стола и уже добавляет депозит к билету для дальнейшей оплаты

## Раздел B. Комиссия платформы (1.5%)

### B.1. Как технически снимаем комиссию?

QRM-ключ у каждого организатора свой, деньги идут сразу ему. Варианты сбора комиссии:

- [ ] **(a) Постфактум-инвойс.** Раз в месяц/неделю считаем оборот, выставляем счёт организатору на 1.5%. Он оплачивает отдельно (по реквизитам / через наш же QRM-ключ). — **Проще всего в MVP.**
- [ ] **(b) Split-платёж через QRM.** Нужно узнавать у QRM — поддерживают ли сплит (автосписание комиссии с транзакции). Возможно, требует статус платёжного агента.
- [ ] **(c) Наш QRM-ключ — деньги сначала к нам, потом переводим 98.5% организатору.** Юридически сложно (нужна лицензия платёжного агента ЦБ).
- [ ] **(d) Фикс-абонплата вместо %.** Например, 2000 ₽/мес/организатор, никакой комиссии с продаж. Проще операционно.
- [ ] **(e) Гибрид:** фикс-абонплата + опциональная комиссия.
- [ ] **(f) Не брать ничего в MVP**, разберёмся потом (просто показывать оборот организатору).
- [ ] Не знаю, выбери ты
- [x] Свой вариант - В системе указан по QRM ключ каждая организация пополняет свой счет, общая коммисия 1,5%. 0,7 это % от QRM списывается при зачислении организатору и 0,8% мой процент который списывает с кошелька в ЛК

## Раздел C. Поддомены организаторов

### C.1. Как работают поддомены?

- [] **(a) Wildcard subdomain на одном приложении.**

  Организатор может привязать свой домен (CNAME `tickets.mybrand.ru` → наш сервер) + свой логотип, цвета. SSL через Let's Encrypt автоматически. — **Круто, но +1-2 недели работы.** Возможно, платная фича.
